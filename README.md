# Линия

Небольшой сайт и панель управления VPN на VPS `217.60.19.243`.

Исходный код: [divangames/lines-](https://github.com/divangames/lines-).

## Локальный запуск

Нужны Node.js 22.12+ и Python 3.11+. На Windows из PowerShell:

```powershell
npm ci
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.venv\Scripts\python.exe scripts/bootstrap.py
.venv\Scripts\python.exe -m uvicorn server.app:app --host 127.0.0.1 --port 8088 --no-access-log
```

Во втором терминале выполните `npm run dev` и откройте `http://127.0.0.1:5173`. Локальные данные владельца записываются в `private/admin-access.json`; конфигурация — в `private/server.json`. `bootstrap.py` не перезаписывает существующую конфигурацию. На Linux используются соответствующие команды из `.venv/bin/`.

Локальный запуск позволяет проверять интерфейс, API, личные кабинеты и выдачу доступов. Для работающего VPN нужны настроенное ядро Xray и серверные службы; локальная конфигурация сама их не устанавливает. Рабочая база и конфигурация сервера в репозитории отсутствуют.

Сборка и изолированные проверки:

```powershell
npm run build
.venv\Scripts\python.exe scripts/verify_backend.py
.venv\Scripts\python.exe scripts/verify_accounts.py
.venv\Scripts\python.exe scripts/verify_account_password.py
```

Проверки создают временные базы и не используют действующие персональные доступы. Скрипты развёртывания ниже предназначены для существующего VPS и не нужны для локального запуска.

## Пользование

- Сайт: https://linesonline.pro/
- Админка: https://linesonline.pro/admin
- Данные входа сохранены на компьютере в `E:\VPS\info\LINEA-admin.json` и `LINEA-admin.txt`. Не публикуйте эти файлы.
- В панели нажмите «Новый доступ», укажите имя, срок и общий лимит трафика. Нулевой лимит означает отсутствие ограничения.
- Кнопка копирования в списке и блок «Ссылка для Happ и v2Ray» выдают **URL подписки** `/sub/…`: его можно сразу вставить в приложение. При открытии в браузере он перенаправляет на инструкцию с QR-кодом. Прежние ссылки `/connect/…` также принимаются VPN-клиентами; в браузере они открывают страницу настройки. Ссылка на эту страницу копируется отдельно кнопкой «Скопировать страницу».
- Продление срока и изменение лимита сохраняют ссылку. Приостановка отключает доступ, включая открытые соединения. Перевыпуск меняет ссылку и ключи: сохранённый старый профиль перестаёт работать.
- Архивирование отключает доступ и убирает запись из списка. Общая история расхода и события сохраняются.
- На вкладке «Настройки» можно изменить название, заголовок сайта, ссылку для связи и пароль администратора. Смена пароля завершает все сессии.

Панель показывает реальные байты Xray, состояние открытых VPN-соединений, последнюю активность, открытия персональной страницы и обновления подписки. Показатели обновляются каждые 5 секунд; при достижении квоты возможен перерасход за этот интервал. Открытия страницы не считаются VPN-подключениями. Список посещённых сайтов панель не сохраняет. Часы и сроки в интерфейсе используют Красноярск (UTC+7).

Новые подписки используют VLESS через WebSocket/TLS на 443 и домен `linesonline.pro`. Исходный NaiveProxy сохранён. Его прежние шесть профилей управляются отдельно и не включены в статистику этой панели.

## Домен

`linesonline.pro` и `www.linesonline.pro` направлены A-записями REG.RU на `217.60.19.243`. Caddy выпускает и автоматически продлевает сертификаты Let's Encrypt; `www` перенаправляет на основной адрес с сохранением пути и параметров. В `/etc/linea/config.json` заданы `base_url=https://linesonline.pro` и `server_host=linesonline.pro`: страницы, QR-коды, подписки и VLESS-профили используют домен.

Главная, админка и личный кабинет по старому IP перенаправляют на домен. Старые URL подписок и VLESS-туннели по IP продолжают работать, ключи не менялись. Исходные NaiveProxy-профили и частный DNS остаются доступны по IP. Для уже импортированной подписки достаточно обновления в VPN-клиенте.

Домен подключён сценарием `scripts/bind_domain.py`: `prepare` добавляет HTTPS с резервной копией и плавной перезагрузкой Caddy, `activate` проверяет авторитетные DNS и доверенные сертификаты перед сменой адреса и перезапуском только портала, `status` выводит состояние. Сценарий запускается на VPS, сохранён также в `/root/VPN/portal/bind_domain.py`. Резервные копии: `/root/VPN/backups/domain-20261116T100126889267Z` и `/root/VPN/backups/domain-20261116T100258590600Z`. Проверены HTTPS, редиректы, вход и выход на десктопе и телефоне, подписки по обоим адресам и реальный VLESS через домен и IP; NaiveProxy проверен отдельно. Отчёты находятся в `private/domain-browser-report.json` и `private/domain-vpn-report.json`.

## Реклама, трекеры и российские домены

На сервере установлен AdGuard Home 0.107.80 со списком **HaGeZi Multi NORMAL** (на 16 ноября — 223 869 доменов). DNS слушает только `127.0.0.1:53`, управление — только `127.0.0.1:3000`, с паролем из локального `E:\VPS\info\LINEA-filter.json`. Публичных DNS-портов нет. Журнал DNS и статистика посещённых доменов отключены. DNS самого VPS не изменён: отдельная конфигурация резолвера подключена только к службам NaiveProxy и Xray.

Xray блокирует домены также по HTTP/TLS/QUIC-имени без расшифровки HTTPS. DNS по TCP/UDP 53 внутри VLESS направляется в фильтр. В исходных Naive TUN JSON настроен собственный фильтрованный DNS по HTTPS с секретным адресом; старые установленные JSON нужно заменить обновлёнными из `E:\VPS\VPN\naiveproxy-clients.zip`. Нативный SOCKS-клиент Naive получает фильтрацию при передаче имени серверу; приложения с собственным зашифрованным DNS и готовыми IP могут обходить эту DNS-фильтрацию.

Подписки передают клиентские правила прямого выхода для `.ru` и `.рф` (`xn--p1ai`), включая поддомены: Happ получает `happ://routing/onadd/…`, v2RayTun — Base64 правил подписки. В Happ активируется **Linea — RU direct**. В v2RayTun правила прикрепляются к подписке и не появляются отдельным профилем: используется выход `direct`, как в актуальной документации клиента. На Windows 3.10.15 оставьте «Маршрутизация → Общий режим → Всё через VPN»: это выход по умолчанию, поверх которого работают исключения подписки. Отдельного режима «По правилам» в этой версии нет. Для применения изменений отключите VPN, обновите подписку «Линия» круглой стрелкой в её карточке и подключитесь заново. Встроенные переключатели `.ru` и `.рф` в «Правилах трафика» для этого включать не требуется. Остальные домены сохраняют выход через VPN. В обновлённых Naive sing-box JSON эти правила уже включены.

После обновления правил на текущем Windows-клиенте проверены реальные запросы: `myip.ru` показывает IP провайдера, совпадающий с прямым выходом через Ethernet, а `api.ipify.org` — IP VPS `217.60.19.243`. В сохранённых правилах активной подписки присутствуют оба суффикса с выходом `direct`. Отдельный запуск установленного ядра v2RayTun дополнительно подтвердил выбор прямого маршрута для `xn--p1ai`.

Прямой трафик не проходит VPS, поэтому сервер не фильтрует и не учитывает его в VPN-трафике. Обход относится к указанным доменным зонам; это не список всех IP российских организаций. DNS-блокировка не гарантирует удаление рекламы, которая загружается с того же домена, что и полезное содержимое, в частности рекламы YouTube.

## Выход YouTube

Для YouTube рабочий сервер использует собственный IPv4-выход. Режим задаётся полем `"egress": "vps-ipv4"` в закрытом файле `/etc/linea/youtube-upstream.json`. Xray направляет домены из `server/youtube.py` в `youtube-direct` с `targetStrategy: ForceIPv4`. Для имён используется серверный DNS-фильтр. Регион YouTube определяется выходом VPS. Подписки и ключи клиентов сохраняются.

VLESS и NaiveProxy используют одинаковое правило. NaiveProxy передаёт соединения через локальный SOCKS Xray `127.0.0.1:1089`. Порядок правил сохраняет блокировки рекламы и частных адресов. Для видео действует прежнее правило перехода с QUIC на TCP.

Резервная копия перед переключением находится в `/root/VPN/backups/youtube-ipv4-20261116T202708Z`. Формат с внешним VLESS в поле `outbound` по-прежнему поддерживается для возврата к прежнему маршруту. При проверке выхода открывайте несколько разных роликов и проверяйте ход таймера и кадры плеера.

## Личный кабинет пользователей

Вход: `https://linesonline.pro/account` по логину и паролю. В админке при создании доступа есть раздел «Вход в личный кабинет»: логин и пароль можно задать вручную или оставить пустыми для автоматического создания. После сохранения в карточке доступа нажмите «Скопировать данные для входа» и передайте их получателю. Пароль показывается только в текущей карточке после создания; при закрытии он убирается. В базе хранится scrypt-хеш, поэтому повторно получить старый пароль нельзя.

Для существующих доступов откройте карточку и нажмите «Создать логин и пароль». Кнопка «Создать новый пароль» сбрасывает забытый пароль и завершает входы в ЛК; VPN-ссылка и условия доступа сохраняются. В «Изменить условия» можно изменить логин или задать новый пароль. Пустой пароль при редактировании сохраняет прежний. Логин состоит из 3–64 латинских букв, цифр, точки, дефиса или подчёркивания; пароль — не менее 12 символов. Логины нечувствительны к регистру и уникальны.

«Запомнить вход на 30 дней» сохраняет защищённую HttpOnly/Secure/SameSite=Strict cookie. Без этой отметки cookie действует до закрытия браузера, а серверная сессия — не более 12 часов. Сессии пользователей и владельца независимы; сброс пароля или смена логина завершает пользовательские сессии. Архивирование отзываёт вход, а истёкший срок, пауза и исчерпание трафика позволяют войти для просмотра причины и продления. Ограничение попыток не сбрасывается успешным входом в другую учётную запись.

Пользователь может самостоятельно сменить пароль в ЛК: раздел «Безопасность» → «Сменить пароль». Нужны текущий пароль, новый пароль не короче 12 символов и повтор нового. После сохранения текущий браузер остаётся в кабинете с новым ключом сессии, остальные сессии пользователя завершаются. Старый пароль и старые ключи сессий перестают работать; логин, VPN-подписка, срок и трафик не меняются. Неправильный текущий пароль ограничен пятью попытками за 15 минут. При входе только по персональной ссылке форма недоступна — сначала нужно войти по логину.

Персональные ссылки остаются рабочими для VPN-приложений и прежних приглашений. `/account/link` сохраняет резервный вход по ссылке, `/connect/…` — прежнюю страницу кабинета. Ссылка по-прежнему является ключом к подписке: храните её как пароль. В кабинет, открытый по логину, можно возвращаться через обычный `/account`, без секретного URL.

В кабинете показаны имя получателя, статус, срок и точное время окончания по Красноярску (UTC+7), остаток и общий расход трафика, полученные и отправленные байты, дата создания, последняя активность и число открытых соединений. Подписка и ссылка на кабинет копируются отдельно; активный доступ сохраняет QR-код и импорт в Happ/v2RayTun. Приостановленный, истёкший и исчерпавший квоту доступ показывают объяснение и возможность сохранить прежнюю ссылку для продления.

Предупреждения отображаются **внутри кабинета**: за 7 дней до окончания, срочные — за сутки; по трафику — при расходе 80% и 95%. По окончании срока или квоты отображается причина остановки. Это не рассылка по почте, Telegram или push. Кнопка продления ведёт на настроенный контакт владельца; без контакта показана инструкция обратиться к тому, кто выдал ссылку. Онлайн-оплаты нет.

Данные обновляются каждые 15 секунд при открытой вкладке и при возвращении в неё. Временная ошибка обновления оставляет последние данные с предупреждением; отзыв ссылки убирает личные данные с экрана. Авторизация добавляет логин и хеш пароля к существующей записи доступа и отдельную таблицу сессий в SQLite. Миграция добавляет поля без изменения VPN-ключей и счётчиков. Для обновления Python-кода перезапускается только веб/API-служба; Xray и NaiveProxy не перезапускаются.

## Сервер

| Назначение | Путь / служба |
|---|---|
| Код и собранный интерфейс | `/opt/linea/server`, `/opt/linea/dist` |
| Конфигурация | `/etc/linea/config.json`, root:linea, 640 |
| Данные | `/var/lib/linea/portal.db`, SQLite WAL |
| Xray | `/opt/linea/bin/xray`, `linea-xray.service` |
| API и WebSocket-шлюз | `linea-portal.service`, 127.0.0.1:8088 |
| Внутренний VLESS / API Xray | 127.0.0.1:10000 / 127.0.0.1:10085 |
| HTTPS и NaiveProxy | `/root/VPN/Caddyfile`, `naiveproxy.service` |
| Архив выпуска | `/root/VPN/portal/release.tar.gz` |
| Резервные копии | `/root/VPN/backups` |
| Частный DNS-фильтр | `linea-filter.service`, `/opt/linea-filter` |
| Обновление списка Xray | `linea-filter-update.timer` |

Обе новые службы работают от отдельного пользователя `linea`, включены в автозапуск. Пароль администратора хранится на сервере как scrypt-хеш. Сессионные cookies Secure/HttpOnly/SameSite=Strict; изменения требуют Origin и CSRF-токен. Ссылки доступа являются секретами и дают их владельцу доступ к конкретной подписке.

Шлюз допускает до 256 одновременных туннелей на один доступ и 512 на сервер. Прежний предел 64 оказался недостаточным при обычной работе браузера: он блокировал новые запросы. В статистике «Открытых соединений» считаются туннели, а не количество устройств.

Проверка состояния: `systemctl status linea-portal linea-xray naiveproxy`. Журналы: `journalctl -u linea-portal -u linea-xray --since today`. HTTP-журнал приложения отключён, чтобы не сохранять URL с ключами. Сертификатами домена и IP и их продлением управляет Caddy.

Согласованную копию базы создаёт `scripts/backup_server.sh` через SQLite backup API; это ручной сценарий, без расписания. Копия остаётся на том же VPS. Перед обновлением кода сохраняются архивы предыдущей сборки. Для переноса потребуется отдельно скопировать базу и `/etc/linea/config.json` в защищённое место.

## Разработка и проверки

React + Vite, FastAPI + SQLite, официальный Xray 26.11.9. Зависимости зафиксированы в `package-lock.json` и `requirements.lock.txt`. Секреты, база, зависимости и архивы не входят в исходники.

`npm run build` собирает интерфейс. `scripts/verify_backend.py` проверяет авторизацию, CSRF, срок, лимит, отзыв и архивирование на временной базе. `scripts/verify_account_password.py` проверяет самостоятельную смену пароля, ротацию сессии, отзыв других устройств, CSRF, ограничения попыток и гонку со сбросом владельцем. `scripts/verify_accounts.py` отдельно проверяет миграцию, пользовательские пароли и сессии, разделение ролей, сброс/смену логина, отзыв и ограничения попыток на временной старой схеме. `scripts/verify_live.py` проверяет реальный туннель через отдельный SOCKS-клиент, не меняя системное VPN-подключение. Сценарии развёртывания рассчитаны на этот VPS и не являются универсальным установщиком.

После включения фильтра выполнены 34 изолированные проверки API и подписок, реальные проверки VLESS/Naive и DNS по TCP/UDP, включая запрос AAAA и TLS с уже известным IP. `scripts/verify_filter_hot_reload.py` отдельно проверяет обновление и возврат списка без рестарта Xray. Настройка фильтра дополняет `install_server.sh`: для чистой установки сначала развёртывают фильтр и его GeoSite-файл, затем портал; установщик портала не заменяет сохранённые drop-in настройки systemd.

Визуальные решения и локальные проверки находятся в `DESIGN.md`, `.impeccable/` и `UNSLOP.md`. Макеты не загружаются на публичный сайт.
